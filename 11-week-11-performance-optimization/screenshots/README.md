# Week 11 — Screenshot Capture Checklist (DevTools)

The Week 11 codelab requires **profiling evidence captured from Flutter
DevTools**, not a widget render. Capture the two files below on a real device
or emulator and place them in this folder with the exact names.

| File | What it must show |
|---|---|
| `before-profile.png` | DevTools → **Performance** tab, flame chart + frame chart of the **Week 10 (unoptimised)** code running the scenario below |
| `after-profile.png` | The **same** DevTools view, same scenario, on the **Week 11 (optimised)** code |

## Procedure

```bash
cd 11-week-11-performance-optimization
flutter pub get

# Profile mode is mandatory — debug mode frame times are meaningless.
flutter run --profile
```

When the app starts, open the DevTools URL printed in the console
(usually `http://127.0.0.1:9100`), then:

1. Go to the **Performance** tab.
2. Press **Record**.
3. Run the scenario end to end:
   - log in → land on the announcement list;
   - fast-scroll the list to the bottom and back to the top (this triggers
     the pagination prefetch);
   - tap an announcement → detail page → back;
   - repeat the list ↔ detail navigation **5×**;
   - pull-to-refresh;
   - open the AI chat and ask one question.
4. Press **Stop**.
5. Screenshot the **frame chart** (green/yellow/red bars) **and** the flame
   chart with the janky frames visible. Make sure the average frame time and
   the number of red frames are readable in the image.
6. Save it as `before-profile.png`.

For `after-profile.png`, repeat 1–6 on the optimised tree (this folder) with
the identical scenario.

## Getting the "before" screenshots

`before-profile.png` must come from the **unoptimised** Week 10 tree. Use a
copy so the optimised folder is not disturbed:

```bash
git clone . /tmp/week10-before
cd /tmp/week10-before/10-week-10-ai-feature-integration
flutter run --profile
```

Then follow the same procedure. If the Week 10 tree is no longer runnable,
keep the measurement honest by profiling the optimised tree **with the
optimisations disabled** (e.g. temporarily return `fetchAnnouncements()`
straight from `_networkRows()` and swap `ListView.builder` back to a full
`ListView`) and note that in `docs/performance-report.md`.

## After capturing

Update the numbers in `docs/performance-report.md` §1 with the values actually
read from the two screenshots, and replace the "illustrative" note there.
`test/screenshots_test.dart` renders `after-profile.png` as a golden, so after
replacing the file either:

- keep the DevTools screenshot under a different name
  (`after-profile-devtools.png`) and point the README at it, **or**
- run `flutter test test/screenshots_test.dart --update-goldens` only if you
  intend the golden to be the UI render (then rename the DevTools capture).
